## M2 oracle clarification

Before M2 execution, oracle 0.2 fixed a non-discriminating cumulative test. The
original task authorized only one ticket, so P3 would reject the second resource
before any cumulative budget could be exercised. A synthetic `task_batch_alpha`
now delegates two ticket resources while retaining a one-customer cumulative
budget. Every P0-P3 profile performs both individually authorized reads and
exceeds the budget. P5 must later distinguish itself by denying the second read.
